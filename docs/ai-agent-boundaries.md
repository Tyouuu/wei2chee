# AI 能决定什么，不能决定什么

> `我觉得要分好跟规划好ai agent能够决定到什么output 然后就是产出的output是要稳定跟对的`
> —— founder，2026-08-25

这份文件把散在十几个档案注释里的那条线，收在一个地方。
**每加一件 AI 能决定的事，就要回来改这份文件，并且在下面第四节加一条量测。**

---

## 一、AI 决定的事（全部）

### 1. 分析阶段 —— `/api/analyze`，客人还没付钱之前

契约在 `lib/openai/analysis-schema.ts`，两层：送给 OpenAI 的 JSON Schema（`strict: true`，
模型**在解码层面**就吐不出别的形状）＋ 我们这边用 Zod 再验一次。

| 它决定 | 范围 | 谁在管 |
|---|---|---|
| `bottlenecks` | 1–4 条，`severity` 只能是 high/medium/low | enum |
| `before_workflow` | 1–8 段，每段 ≤ 6 字（超过就截断，不退回） | maxItems + 截断 |
| `after_workflow` / `_en` | 1–6 段 | maxItems |
| `focus_stage_index` | 整数，指向上面某一段（超界就夹到范围内） | clamp |
| `summary` / `summary_en` | 一句 | minLength |
| `modules` | 4–8 个，`key` **只能**从 16 个固定页面型别里选 | enum + `normalizeModules` |
| `enquiry.lands_in` | 5 个落点或 `"none"`，而且必须是它自己选了的模块 | enum + `normalizeEnquiry` |
| `enquiry.fields` | ≤ 4 题，`kind` 只能是 text/phone/email/date/long | maxItems + enum |

**它同时决定「这门生意的词」**：`label` / `label_en` —— 电话卡总代理的客户叫「经销商」不叫「客户」。
这是它最该做、也最难被规则取代的一件。

### 2. 编辑器阶段 —— 客人已经在改自己的系统

契约在 `lib/portal/layout-ops.ts`。

| 它决定 | 限制 |
|---|---|
| 加一个区块 | 只能是**已注册**的元件名，加错名字整条操作被丢掉 |
| 删 / 移动一个区块 | 不可以删页面框架（`SystemShell`），删了里面全部会掉出去 |
| 换一个区块的款式 | 只能写 `variants.ts` 里存在的那几个 |
| 改文案 `set_copy` | 只能写**已经存在**的 key，只能写字串，凭空造 key 什么都不会发生 |
| 加一行表格资料 | 目标必须真的是一张表格 |
| **加 / 删一整页** | **不是操作，是一个按钮** —— 它只能「提议」，客人自己按，用客人自己的权限写库 |

## 二、AI 永远不能决定的事

1. **版面 JSON。** LLM 从来不吐 Puck layout。页面是这边用资料**算**出来的
   （`lib/templates/industry-template.ts`）。理由写在那个档案开头：一个幻觉出来的元件名
   不是「版面差一点」，是**付了钱的客户打开一张白纸**。Durable 和 B12 在「AI 帮你建站」
   底下也是这么做的 —— 手工设计的原型，AI 负责挑和填。
2. **风格 / 配色。** 16 套版式和 25 套配色是客人自己挑的。
3. **价钱、金额、法律文字。** 官网的价格参考永远是 `RM —`，不是它编的数字。
4. **直接写资料库。** 所有写入走 RPC，用**客人自己的身份**，不是服务端金钥。
5. **跨语言凑合。** 系统语言是英文就全英文。宁可用通用的英文句，不可以中英夹一句。

## 三、坏掉的时候会怎样（这是「稳」的另一半）

- 模型不通 / 连续吐不合格 → `fallbackAnalysis()`：讲这一行**已知**的流程和通用问题，
  **不编**这门生意的细节。理由：一个刚花几分钟答完问卷的人，最贵的失败就是给他看一个错误页。
- fallback 永远不会答 `enquiry.lands_in = "none"` —— 在没有证据的情况下取消一家生意的询价表，
  是另一个方向的编造。
- 落点是这家生意没有的页面 → 退回到它有的第一个卖单页，不是留一个死连结。
- 一句超长的流程名（真的发生过：「佣金核算容易出错，影响结算准确性。」被画成表格栏位）→ 截断，
  不整份丢掉。

## 四、稳定性怎么量（现在的缺口）

**现状：没有量过。** 上面每一条护栏都挡住了「形状错」，
但没有任何东西回答「同一份问卷跑十次，它会不会挑出不一样的模块」。

`npm run eval:analysis` 是补这个缺口的：同一份生意描述跑 N 次，量三件事的一致率 ——

1. **模块选择**（挑了哪几页）
2. **落点决定**（`enquiry.lands_in`）
3. **词汇**（`label_en`，客人自己的名词）

一致率低不代表模型坏，代表**这一题问得不够清楚** —— 该改的是 schema 的 description，不是重跑。

### 第一次实测（2026-08-25，9 次真实呼叫）

| 生意 | 模块组合 | 落点 | 客户的词 | 问几题 |
|---|---|---|---|---|
| 装修承包商 | 100% | 100% `quotations` | 100% `Clients` | 100% |
| 电话卡总代理 | 100% | 100% **`orders`** | 100% `Dealers` | 100% |
| 咖啡店 | 100% | 100% **`none`** | 100% `Customers` | 100% |

**四项全部 100%，三个生意各只出现一种模块组合。**

两个数字值得单独看：

* 电话卡总代理答的是 **`orders` 不是 `quotations`** —— 而 2026-08-25 之前那个写死的数组
  （`["quotations","bookings","orders","projects"].find`）一定会给 quotations，因为它排前面。
  这一栏是「熟客直接 WhatsApp 我要多少」这句话的答案，不是数组顺序的答案。
* 咖啡店答的是 **`none`** —— 它自己判断「都是走进来的街坊」的生意不该有询价表。
  这是当天才加的选项，也是它最没有理由去选的一个。

**基线记在这里。** 以后改 schema 的 description、换模型、加栏位，重跑一次跟这张表比 ——
掉下去就是那次改动的代价，不是运气。

### 外面怎么做（2026-08-25 实地查的）

| 项目 | ★ | 许可 | 语言 | 我们要不要 |
|---|---|---|---|---|
| **promptfoo** | 24.5k | MIT | **TypeScript** | **值得** —— 唯一跟我们同栈又活跃的 eval 跑法 |
| deepeval | 17.8k | Apache-2.0 | Python | 换语言，暂不 |
| openai/evals | 19.2k | NOASSERTION | Python | 许可不明 + 一年没大动 |
| langfuse | 33.6k | NOASSERTION | TypeScript | 是观测平台，等有真实用量再说 |
| dspy | 37.6k | MIT | Python | 是「编程代替提示词」，跟我们的 schema 路线重叠 |
| outlines / instructor / guidance | 15.7k / 13.8k / 21.7k | Apache-2.0 / MIT / MIT | Python | **不需要** |

最后一行是重点：`outlines`、`instructor`、`guidance` 卖的就是「强制模型吐固定结构」。
**我们已经有了** —— OpenAI 的 `strict: true` 是在解码层面做的，比这三个库更硬，
外加一层 Zod 复检和一层校正。所以我们缺的从来不是约束，是**量测**。
