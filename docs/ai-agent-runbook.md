# AI agent —— 怎么维护，坏了怎么查

配套：[能决定什么、不能决定什么](./ai-agent-boundaries.md)（那份讲**边界**，这份讲**运维**）。

三个地方在花老板的 OpenAI key：

| surface | 在哪 | 多久一次 | 坏了客户看得到吗 |
|---|---|---|---|
| `analyze` | `app/api/analyze` | 每个客户一次（注册时） | **看不到** —— 有 fallback，照样出一套系统 |
| `edit` | `app/api/portal/edit` | 每讲一句话一次 | 看得到 —— 他会读到一句话 |
| `spec` | `app/[locale]/portal/(app)/spec` | 每次打开需求书 | **看不到** —— 文件照样渲染，只是少一段散文 |

⚠️ **三个里有两个坏了客户不会讲。** 这就是 `ai_usage` 要记失败的原因。

---

## 一、平常要跑的

```bash
npm run eval:editor -- --n 2    # 47+ 题真呼叫。听得懂 / 改到了 / 每次一样 + 延迟 + token
npm run eval:analysis           # 问卷那一端的一致率
npm run check:ai-cost           # 花了多少 · 坏了几次 · 他等多久
npm run eval:editor -- --prefix # 不花钱：prompt 有多少可以重用
npm run shoot:assistant         # 不花钱：面板在等待 / 断掉的时候长什么样
npm run eval:browser            # 真浏览器：它说改了，画面真的动了吗
```

### ⚠️ `eval:browser` 是唯一能回答那一段的尺

它量的不是伺服器回的 JSON，是 **画布上人看得见的字**（`innerText`）。
两条断言，第一条就是那九次 bug：

| 它说什么 | 画面必须 |
|---|---|
| 宣称改了 | **一定要不一样** |
| 拒绝 / 反问 | **一定要一样** |

第一天跑就抓到两件：助手改完自己关掉、排法写进了资料库但画布不动。
**两件 `eval:editor` 都报 100%。**

→ 要先开着 `npm run dev`。它会把 demo 账号的风格/配色/排法存一份、跑完放回去；
**不会保存任何页面** —— AI 的修改在按下「保存设计」之前只活在浏览器里。

**什么时候一定要跑 `eval:editor` 全套：**
- 改了 `SYSTEM_PROMPT` 任何一句 —— **一律全套，不要只跑你瞄准的那题**
- 换模型或改 `reasoning_effort`
- 加/删组件、改 `layout-ops.ts` 的操作
- 改 `block-rules.ts`

**为什么一定要全套**：2026-08-27 我把「不准画死按钮」那条边界收窄，瞄准两题，
**副作用出现在第三题**（「我要知道这个月收多少钱」从加一块变成拒绝）。
**改一句 prompt，影响范围没办法从 diff 推出来。**

**为什么 `--n 2` 起跳**：n=1 的时候「每次一样」那一栏**没有第二个答案可以比**，
每一行都印 100%。它量的是自己的盲点，不是助手。跑两次掉到 96%，
而掉下来的三行里有一行是真 bug。

## 二、坏了先看哪里

### 症状 1 —— 客户说「AI 改不了」
```bash
npm run check:ai-cost
```
- **失败率高** → provider 那边，或我们这边 500。看 Vercel log 的 `layout edit failed`
- **失败率 0，客户还是抱怨** → 🔴 **这是最危险的一种**：模型答对了，浏览器把答案扔掉了。
  **这个仓库九次断线全部发生在这一段。** 尺子量的是 route 回的 JSON，**从来不开浏览器**，
  所以它会一片绿地报告 100%

### 症状 2 —— 「它说改了，画面没动」
最严重的一类，因为**一个宣称做了却没做的助手，比拒绝还糟**。查的顺序：
1. route 回的 `skipped` —— 我们这边挡下来的，理由写在里面
2. **前端有没有消费那个字段** —— `design.layout` 就是这样丢了三个月：
   prompt 教了、schema 带了、`validDesign` 校验了、RPC 早就在，
   **只有浏览器那一段没读它**
3. `design-change.test.ts` 的 `it.each(DESIGN_FIELDS)` 就是防这一类的 ——
   任何新增的 design 字段没有 RPC 落点就红

### 症状 3 —— 「等很久没反应」
- `check:ai-cost` 看 `took_ms` 的 p95（真实客户的）
- `eval:editor` 底下那行看开发机的
- 两条 route 的 `maxDuration = 60`，浏览器 45 秒放弃并且给他一颗「不等了」
- **2026-08-27 实测基线**：中位 4.0s · p95 8.0s · 最慢 12s（最慢的都是带图的）

### 症状 4 —— 「它乱改东西」/「它该问却自己猜」
跑全套 eval，看是哪一题掉。多半是 prompt 某条规则**边界画太宽或太窄**。
判准写在 prompt 里：**问了会不会得到答案** ——
「你帮我弄好看一点」不会（所以动手），「金额那边怪怪的」会（所以问）。

### 症状 5 —— 中英混着讲
`replyIn` 那几题。规矩是**不跨语言凑合**：拿不到英文就退回通用句，不要拿中文顶上去。

## 三、改东西的规矩（都是踩过才写下来的）

1. **期望写错了，在注解里写清楚为什么改**，不要偷偷改掉。
   我改过五次尺子，其中三次是**我自己的期望错了** ——
   「把作者的偏好写成正确答案，尺子就不再量产品，开始量作者」
2. **不要在 prompt 里写会过期的事实。** 「深色配色只有 X」写死过一次，
   三小时后就开始拒绝正确答案。现在从配色档**算出来**再注入
3. **一把坏掉的尺，照样印出一个跟好的一模一样的数字。**
   `oklch` 被当 hex 解析（`parseInt("kl",16)` → NaN），三次跑过一次。
   是「三次答案完全一样却只过一次」这个矛盾才让我回头查的
4. **换模型 → `lib/portal/ai-model.ts` 一个地方**，然后照那个档头的三步走
