# 助手的边界 —— 它能做什么、不能做什么、为什么

由[任务 393](./founder-tasks.md#393) 引入。他问「助手的边界是什么，是不是要定下来」，
这份就是答案——不是散在各处的判断，是一张写清楚的表。

⚠️ **这份只管产品那一边的助手**（`surface: "work"`，他自己系统里做事的那一支）。
改设计那一屏（`surface: "design"`）是另一支，边界不一样，这里不重复。

---

## 一、它真的写得进他的帐的（27 个动词，2026-09-11 数的）

每一个都走**人按同一颗按钮会打的那一支资料库函式**（重点 23：AI 平权），
没有第二条写入路径。分成七组：

| 组 | 动词 | 一句话 |
|---|---|---|
| **单据** | `add_table_row`（含九行明细）· `add_record_line` · `set_record_status` · `bill_class` · `take_payment` · `reverse_ledger_entry` | 开一张单、往单上加一行、改阶段、给全班开学费单、收钱、撤销一笔钱（开相反的一笔，不删） |
| **预约** | `book_appointment` · `set_appointment_deposit` · `set_appointment_archived` · `mark_appointment_arrived` | 排一笔、要不要先收订金、取消（收起来不删）、标她到了 |
| **客户** | `claim_booking_party` · `add_treatment_note` · `request_consent` · `grant_credit` · `use_credit` · `set_party_alert` | 官网/WhatsApp 进来的认成客户、记一笔疗程、发一份同意书、送/用一笔储值、挂一句提醒 |
| **师傅** | `clock_in` · `clock_out` | 打卡上下班 |
| **跟进** | `set_follow_up` · `finish_follow_up` · `drop_follow_up` · `reply_to_enquiry`（只起草，不发送） | 记下一步、做完了、不追了、起草一句回覆配一条连结，他按了才送出去 |
| **进货/库存** | `receive_purchase` · `count_stock` | 收货、盘点 |
| **记性** | `remember` · `forget_that` | 记住一条规矩、忘掉一条 |
| **只读** | 全部 `live-answers.ts` 里的数字 · 十四种主动讯号 · 今天要跟的三件 | 答他的问题，一个字都不动他的帐 |

**每一个都走过同一条流程**：真身份呼叫一次 · 打开浏览器看 · 故意拔掉看它红 ·
放回去看它绿。清单本身在代码里有四份手写的对照（zod · 处理逻辑 · 送给模型的
schema · 送给模型的动词名单），一支尺子（`op-lists-agree.test.ts`）守着它们
不会漂。

## 二、只做「起草，他按了才送出去」的（一个）

`reply_to_enquiry` 是目前唯一一个**碰他客人**的动词——它不直接跟陌生人讲话，
只起草一句回覆配一条填好字的 WhatsApp 连结，他自己看过、自己按送出。
这是[重点 32](./founder-points.md) 那句「他最怕的就是机器人对我的客人讲话」
定下来的形状：起草＋他按，不是自动前台。

**这一条边界不是技术限制，是故意的。** 底下的「明确不给它碰的」第二类
会再讲一次为什么。

---

## 三、明确不给它碰的，两种不一样的理由

### A. 根本不是它的地盘（结构性排除，不是判断）

| 类别 | 例子 | 为什么 |
|---|---|---|
| 改设计那一屏的动词 | `set_text` · `add_component` · `move_component` · `set_variant` · `set_copy` 等十个 | 他站在自己系统那一页时没有编辑器，这些动作在那里天生做不到（`WORK_OPS` 集合结构上就没收它们，不是运行时判断） |
| 客户自己在官网上按的 | `submit_site_booking` · `submit_site_enquiry` · `submit_appointment_review` · `submit_party_request` | 那是**陌生人的**入口，走的是完全不同的身份（匿名、限流、不认识他），不是助手替他按的 |
| 内部管线函式 | `add_ledger_entry_core` · `log_record_change` · `update_pipeline_record` · 单独的 `update_appointment` | 这些是给别的函式调用的零件，不是一句人话对得上的动作——没有对应的「他会怎么说」 |

### B. 危险，故意不给它决定（这是我这边的判断，也是这份文件真正的内容）

| 动作 | 为什么不给 | 谁来做 |
|---|---|---|
| 帐号 / 权限管理 | `add_project_member` · `set_member_active` | 决定谁能登入他的系统，是身份跟信任层的事，不该靠一句话 |
| 钱怎么分摊 | `set_payment_allocations` | 一笔钱该记在哪一期、哪一张单，算错了整本帐的欠款全部跟着错 |
| 薪资 | `set_payslip_earnings` | 直接影响他付给员工多少钱，错一次是真的少发或多发 |
| 开帐期初数 / 税务身份 | `set_opening_balance` · `set_tax_profile` | 一次性、改了会牵动过去所有的对帐 |
| 同意书 / 范本原文 | `add_consent_form` / `update_consent_form` 的内容 | 那是医疗上的宣称，我们不是诊所，一个字都不该是我们编的（[任务 309]） |
| 员工执照 / 资格 | `set_staff_credential` | 谁能打肉毒、谁能碰哪一种疗程，是法规问题不是记账问题（[任务 341] 那四件风险） |

**这两类的差别要讲清楚**：A 类哪天技术上通了（比如助手接进产品每一页），
边界还是不会动——那从来不是「做不到」，是「不该做」。B 类才是真的判断，
换句话说，如果哪天他明确要放宽某一条（比如放宽薪资），那是**他的决定**，
不是我自己判断技术上能不能做。

## 四、审计——分得清是他自己按的还是助手做的，但有一个真的洞

`record_changes` 那张表（[任务 370](./founder-tasks.md#370)）能分——助手发出的
每一个写入请求都带一个只有它会送的记号（`x-formae-actor: assistant`），
改动落在走单·名册·钱·预约四张表时会照实标。

🔴 **但今晚新建的打卡表（`staff_shifts`）还没接上这张审计表** ——
不是「分不清是谁打的卡」，是那张表压根还没进这个机制，`clock_in` /
`clock_out` 改动的东西现在完全没有历史可查。这不是我这边能单独接的
（跟另外那三张表同一条规矩，是资料库那一边的活），已经登记给功能地基
那个 session。

## 五、老板跟员工各自按得到什么（钱这一块，2026-09-24 定的）

助手走的是**登入的人自己的身份**，所以员工叫助手做事，做得到的就是员工自己按得到的——
权限住在资料库，不在助手身上（重点 23）。钱这一块今天是这样：

| | 老板 | 员工（在职） |
|---|---|---|
| **记一笔客人付的钱**（`take_payment` · 收银台「结帐」） | ✅ | ✅ 任务 411 放宽的，记的是员工自己 |
| 记一笔开销 · 付供应商 · 佣金 | ✅ | ❌ 付出去的钱是决定，不是收下 |
| 撤销一笔钱（`reverse_ledger_entry`） | ✅ | ❌ 员工按错了要请老板撤 |
| 改一笔钱上的备注 · 方式 | ✅ | ❌ |
| 看「今天收了多少」（总览 · 每日结帐） | ✅ | ❌ |

守卫：`npm run check:ledger-staff`（22 条，含陌生人、离职员工、员工拿老板的钥匙重播）。
⚠️ 员工叫助手「收一笔钱」之后想撤销那一步（面板上的撤销键）会被资料库挡下——
它走的是 `reverse_ledger_entry`，跟上面那一行同一条。

## 六、还没定案、要他决定的

- [ ] 员工能不能自己撤销自己按错的那一笔收款——今天要请老板。一间店的柜台按错一笔
      是天天会发生的事，而每次都要老板动手，是下一个会被问到的
- [ ] `reply_to_enquiry` 现在是「起草＋他按」——要不要有一天放开成客人
      直接跟机器人讲话（自动前台），是[重点 32](./founder-points.md) 那句
      「他最怕机器人对客人讲话」明确挡住的，除非他自己推翻
- [ ] `grant_credit` 今天只有老板按得到（`sees_money`）——他讲过储值送多少
      的规矩之后，要不要放宽给柜台，是[任务 334] 记着的决定
- [ ] `staff_shifts` 的审计洞——上面第四点，等功能地基接上
